## 三、系统架构设计

### 3.1 整体架构层次

整个系统分为四层：

```
前端层 (React + Vite)
    用户界面: Dashboard / 计划管理 / 路径图 / 反馈对话 / 画像页面
        |
        | HTTP / SSE / WebSocket
        v
API 网关层 (FastAPI)
    鉴权 / 路由 / 请求校验 / SSE 流式推送
        |
        v
业务与智能体层 (LangGraph)
    -- 业务服务层: 用户管理 / 计划 CRUD / 任务管理 / 会话管理
    -- 多智能体层:
       Orchestrator Agent (网关编排)
          +-- Profile Agent (画像构建与维护)
          +-- Plan Agent (路径规划)
          +-- Schedule Agent (排期生成)
          +-- Feedback Agent (反馈分析)
          +-- Intervention Agent (干预恢复)
        |
        v
存储层
    PostgreSQL / SQLite (关系型)
    ChromaDB (向量)
    Redis (缓存/队列)
    文件系统 (日志/导出)
```

### 3.2 多智能体架构

系统采用 Orchestrator 编排模式：一个网关智能体统一接收用户请求，根据意图分发到各专业智能体。

```
用户输入 (HTTP/WS)
    |
    v
Orchestrator Agent (网关编排智能体)
    意图识别与路由 / 会话状态管理 / 多 Agent 调度协调 / 结果聚合与响应生成
    |
    +------+------+------+------+------+
    |      |      |      |      |      |
    v      v      v      v      v      v
Profile  Plan  Schedule Feedback Intervention
Agent   Agent   Agent    Agent     Agent
(画像)  (路径)  (排期)   (反馈)   (干预)
    |      |      |      |      |
    +------+------+------+------+------+
                    |
                    v
              LLM Service (ChatOpenAI)
```

#### 各智能体职责

| 智能体 | 核心职责 | 数据依赖 |
|--------|---------|---------|
| **Orchestrator Agent** | 意图分类 + 子图路由 + 会话记忆管理 | 用户输入、会话上下文 |
| **Profile Agent** | 多维度画像推算 + 标签演化 + 画像漂移检测 | 反馈历史、打卡时间、任务完成率 |
| **Plan Agent** | 目标结构化解析 + 知识图谱生成 + 基于画像的路径调优 | 学习目标、画像数据 |
| **Schedule Agent** | 多计划优先级排序 + 时间段优化 + 冲突消解 | 活跃计划、画像时段偏好、时间预算 |
| **Feedback Agent** | 画像感知追问生成 + 反馈信号语义解析 + 掌握度推断 | 画像数据、当前学习内容、反馈历史 |
| **Intervention Agent** | 中断检测 + 恢复方案生成 + 遗忘曲线排期 | 画像持续力数据、中断记录 |

#### 智能体状态设计

每个智能体基于 LangGraph StateGraph 运行：

```python
class AgentState(TypedDict):
    """通用智能体状态基类"""
    messages: list[BaseMessage]       # 对话历史
    user_id: str                       # 当前用户
    plan_id: str | None                # 当前计划上下文
    session_id: str                    # 当前会话 ID
    agent_type: str                    # 智能体类型标识
    tools: list[Tool]                  # 可调用的工具集
    next: str                          # 下一步路由目标

class FeedbackAgentState(AgentState):
    """反馈分析智能体扩展状态"""
    feedback_signal: str | None        # 解析后的信号
    confidence_delta: float            # 掌握度变化量
    replan_triggered: bool             # 是否触发重规划
    profile_update: dict | None        # 待更新的画像维度
```

### 3.3 智能体间通信

智能体间通过 Orchestrator 中介通信，不使用点对点调用：

- **同步调用**：用户直接发起的交互（创建计划、提交反馈），LangGraph 串行执行子图
- **异步事件**：系统内部触发的动作（每日 0 点排期生成、中断检测），APScheduler 推入队列
- **SSE 推送**：异步事件完成后，通过 Server-Sent Events 实时推送到前端

典型通信路径：

```
用户 -> Orchestrator -> Profile Agent -> Orchestrator -> 用户
用户 -> Orchestrator -> Plan Agent -> Orchestrator -> 用户
用户 -> Orchestrator -> Feedback Agent -> Orchestrator -> Profile Agent (异步更新画像)
                                              -> Schedule Agent (异步重排期)
                                                 -> Orchestrator -> 用户 (SSE 告知调整)
```

## 四、完整功能清单

### P0 — 核心闭环（必须实现）

#### A. 多计划创建与优先级管理

| 编号 | 功能 | 技术实现要点 |

| A2 | 优先级管理 | 整数优先级字段(1-3)，排期 Agent 按优先级权重 + 画像时段偏好 分配时间段 |

| A4 | 计划列表与编辑 | React 表格展示 + 行内编辑，zustand 管理本地状态 |

#### B. 用户画像构建

| 编号 | 功能 | 技术实现要点 |
|------|------|-------------|
| B1 | 画像维度建模 | Pydantic dataclass 定义固定维度 + 动态标签体系，向量化存储到 ChromaDB |
| B2 | 初始画像构建 | Profile Agent 通过 3-5 个自然语言问题摸底，生成本地画像快照存储到 PostgreSQL |
| B3 | 画像持续进化 | Feedback Agent 交互后异步传给 Profile Agent，增量更新策略，附带置信度分数(0-100) |
| B4 | 画像展示 | React + ECharts 可视化仪表盘，展示各维度标签值和置信度，标注画像更新时间线 |
| B5 | 画像反馈校准 | 用户可对单个标签点踩，Profile Agent 下调该维度置信度并重新采数 |

#### C. 目标设定与可行性评估

| 编号 | 功能 | 技术实现要点 |
|------|------|-------------|
| C1 | 自然语言目标解析 | Plan Agent 接收用户输入，调用 LLM 结构化提取目标领域、预期时间、当前基础、期望深度 |
| C2 | 知识图谱节点生成 | Plan Agent 调用 LLM 将目标拆解为依赖拓扑图(DAG)，每个节点为 atomic learning unit |
| C3 | 可行性评估 | Plan Agent 结合 Profile Agent 输出的画像数据，生成自然语言评估报告 |

#### D. 学习路径自动生成

| 编号 | 功能 | 技术实现要点 |
|------|------|-------------|
| D1 | 路径拓扑生成 | Plan Agent 基于知识 DAG 输出有序的知识节点列表，标记预估学时和前置依赖 |
| D2 | 路径交互可视化 | React Flow 或 dagre-d3 渲染 DAG 图，支持拖拽、缩放、节点选中 |
| D3 | 用户路径干预 | 用户可标记跳过或优先学习，Plan Agent 重新拓扑排序 |
| D4 | 画像自适应路径 | 路径时间估算乘以画像系数(稳健型 1.3x，冲刺型 0.8x，间歇型插入 20% 缓冲日) |

#### E. 每日排期与多计划时间协调

| 编号 | 功能 | 技术实现要点 |
|------|------|-------------|
| E1 | 日排期自动生成 | APScheduler 每日 0 点触发，Schedule Agent 遍历所有活跃计划按优先级分配当日任务 |
| E2 | 多计划协调算法 | 时间冲突时低优先级让步；同优先级按画像时段偏好分配(早/中/晚/通勤) |
| E3 | 手动拖拽调整 | 前端 drag & drop 重排，画像更新 Schedule Agent 的时段偏好权重 |
| E4 | 时间预算溢出检测 | 总预算超可用时间时按优先级比例压缩，前端 toast 通知 |

#### F. 智能感受反馈

| 编号 | 功能 | 技术实现要点 |
|------|------|-------------|
| F1 | 画像感知追问生成 | Feedback Agent 加载当前画像快照 + 学习内容，调用 LLM 生成开放式追问，SSE 流式返回 |
| F2 | 反馈对话流 | 前端对话气泡展示追问，用户输入文本后 Feedback Agent 语义解析和追问(最多 3 轮) |

## 五、存储层设计

### 5.1 存储架构

采用分层存储设计，按数据类型选择最优存储方案：

| 存储类型 | 用途 | 技术方案 |
|---------|------|---------|
| 关系型 | 用户、计划、会话、任务 CRUD | SQLAlchemy ORM + PostgreSQL |
| 向量型 | 画像语义向量、知识节点语义搜索 | ChromaDB |
| 缓存型 | Session 状态、临时排期、频繁查询 | Redis |
| 文件型 | 导出文件、日志归档 | 本地文件系统 |

### 5.2 数据实体关系

```
User (1) ----------- Plan (N)             一个用户拥有多个学习计划
Plan (1) ----------- KnowledgeNode (N)   一个计划包含多个知识节点
KnowledgeNode ------ KnowledgeNode (M:N) 前置依赖关系(DAG)
User (1) ----------- DailyTask (N)       一个用户每天有 0-N 个任务
Plan (1) ----------- DailyTask (N)       一个计划包含多个每日任务
User (1) ----------- FeedbackSession (N) 一个用户有多轮反馈对话
User (1) ---------1 UserProfile (1)      一个用户只有一份当前画像
```

## 六、API 接口设计

### 6.1 接口规范

- 基础路径：/api/v1
- 认证方式：JWT Bearer Token
- 响应格式：统一 { code: int, data: any, message: string }
- 流式响应：反馈对话使用 SSE (/api/v1/feedback/stream)

### 6.2 核心接口列表

#### 用户模块

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/v1/auth/register | 注册 |
| POST | /api/v1/auth/login | 登录，返回 JWT |
| GET | /api/v1/auth/profile | 获取当前用户 |

#### 计划模块

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/v1/plans | 创建计划 + 触发 Plan Agent 生成路径 |
| GET | /api/v1/plans | 列出用户所有计划 |
| GET | /api/v1/plans/{id} | 获取计划详情(含完整路径 DAG) |
| PATCH | /api/v1/plans/{id} | 更新计划 |
| DELETE | /api/v1/plans/{id} | 删除计划 |
| POST | /api/v1/plans/{id}/assess | 对计划目标进行可行性评估 |

#### 路径模块

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/v1/plans/{id}/path | 获取路径 DAG |
| PATCH | /api/v1/plans/{id}/path/nodes/{nodeId} | 操作路径节点(跳过/优先/标记) |

#### 每日任务模块

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/v1/tasks/today | 获取今日任务列表 |
| GET | /api/v1/tasks?date=YYYY-MM-DD | 按日期查询任务 |
| PATCH | /api/v1/tasks/{id} | 更新任务状态 |
| PUT | /api/v1/tasks/today/reorder | 手动拖拽重排 |

#### 反馈模块

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/v1/feedback/stream | SSE 流建立反馈对话连接 |
| POST | /api/v1/feedback/start | 开始反馈对话(传入 task_id) |
| POST | /api/v1/feedback/reply | 用户回复反馈追问 |

#### 画像模块

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/v1/profile | 获取当前画像 |
| GET | /api/v1/profile/history | 获取画像变更历史 |
| POST | /api/v1/profile/calibrate/{dimension} | 用户对某维度画像提出异议 |

#### 学习日记模块

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/v1/journals | 创建学习日记 |
| GET | /api/v1/journals?node_id=X | 按知识节点查询日记 |
