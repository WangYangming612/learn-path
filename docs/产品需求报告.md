# 个性化学习路径动态生成系统 — 产品需求报告

> 产品定位：AI 学习助理 — 你只管学，剩下的交给我
>
> 版本：v1.1 | 日期：2026-07-22 | 状态：修订稿

---

# 第一部分：产品概述

## 1.1 一句话定义

**一款面向自学者的 AI 学习助理，通过多智能体协同编排，为用户提供多计划管理、每日智能排期、学习反馈驱动的动态路径调整，以及长期学习追踪与干预服务。**

它不是内容平台——不生产课程、不录制视频、不托管资源。它只负责一件事：帮用户安排好"学什么、什么时候学、学得怎么样"，让用户只需要专注于"学"本身。

## 1.2 核心洞察：为什么自学者需要这样一款产品

自学的真正困难，从来不是"找不到资源"。互联网上免费课程泛滥。自学的困难是这三个：

| 困难 | 具体表现 | 现有方案的问题 |
|------|---------|---------------|
| 启动迷茫 | 想学但不知从哪开始，花大量时间做攻略而非学习 | 攻略看完了，热情也耗尽了 |
| 多线失序 | 同时想学编程+英语+健身，时间安排一团乱 | 用日历或备忘录手动排，维护成本高 |
| 坚持无力 | 中断一次就彻底放弃 | 没人提醒、没人拉一把、看不到进度 |

市场上不缺学习打卡App和课程平台，但缺一个把"规划-执行-反馈-调整"闭环跑通、且能同时管理多个学习计划的产品。

## 1.3 产品核心价值主张

> 你只管学，剩下的交给我。

展开来说：

- 不用做攻略 — 告诉系统目标，系统给你拆成可执行的每日计划
- 不用手动排期 — 多个计划的时间冲突，系统自动协调
- 不用纠结调整 — 只需要描述真实感受，系统基于对你的了解智能追问，自动重算后面的安排
- 不用担心遗忘 — 系统记得你学过什么，到时间安排复习
- 不用担心中断 — 断了回来，系统帮你平稳恢复

用户只需要做两件事：学，以及学完后回来说说学得怎么样。

# 第二部分：目标用户分析

## 2.1 核心用户画像

| 画像类型 | 具体描述 | 典型场景 | 关键需求 |
|---------|---------|---------|---------|
| 多线自学者 | 职场人，同时在学习2-3项技能 | 白天上班晚上自学，时间碎片化 | 多计划协调、每日智能排期 |
| 转行者 | 决心换赛道，3-6个月内系统掌握新技能 | 脱产或半脱产学习，目标明确 | 完整路径规划、可行性判断 |
| 大学生拓界者 | 主修之外自己加码，同时备考+学技能 | 课业之余挤时间，经常被考试打断 | 中断恢复、优先级管理 |
| 间歇性学习者 | 想学但坚持不下来，学一阵停一阵 | 热情期猛学2周然后停1个月 | 低门槛恢复、长期追踪 |

## 2.2 非目标用户

- 依赖系统提供课程内容的用户：这不是在线教育平台
- 只需要一个简单 Todo 的用户：滴答清单更适合他
- 已经有一套成熟自我管理体系的极少数自律者：不需要工具辅助

# 第三部分：功能全景

## 3.1 功能总览图

第一层：核心闭环 (P0)
  ① 多计划创建与优先级管理
  ② 用户画像构建（新增）
  ③ 目标设定与可行性评估（基于画像）
  ④ 学习路径自动生成（基于画像）
  ⑤ 每日排期与多计划时间协调
  ⑥ 智能感受反馈（重构：固定选项改为AI生成式追问）
  ⑦ 反馈驱动的即时重规划

第二层：增强体验 (P1)
  ⑧ 遗忘干预（艾宾浩斯复习）
  ⑨ 学习重点指引（重构：去掉具体链接，仅提供方向性指导）
  ⑩ 学习日记（一句话笔记）
  ⑪ 中断恢复模式（基于画像个性化恢复方案）
  ⑫ 每周学习简报（含画像更新说明）
  ⑬ 学习画像展示与进化（用户可见的画像页面）

第三层：深度价值 (P2)
  ⑭ 学习效率分析
  ⑮ 计划可行性诊断
  ⑯ 跨计划知识关联识别
  ⑰ 自定义里程碑

## 3.2 第一层：核心闭环（P0，必须实现）

### 功能 ①：多计划创建与优先级管理

用户需求：同时学2-3样东西，但精力有限，需要分清主次。

功能描述：
- 用户可创建多个学习计划，每个计划独立设定名称、目标、起止日期
- 每个计划设置优先级（三星/二星/一星）
- 每个计划设置每日时间预算（如Python每天30min，英语每天20min）
- 每个计划设置时间段偏好（早上/中午/晚上/周末）

交互要点：
- 创建计划的流程不超过3步
- 优先级和预算可以随时调整
- 系统在创建时提供实时估算：你目前已有2个计划总计需要65min/天，每日总可用90min，还有空余
- 新计划创建后，系统结合用户画像给出个性化建议：根据你过去的学习记录，你习惯在晚上集中学习，建议将这个计划安排在20:00之后

### 功能 ②：用户画像构建

用户需求：系统凭什么给我推荐这些？它真的了解我吗？我想知道自己是一个什么样的学习者。

设计动机：这是整个智能体系的地基。没有用户画像，所有的"智能"都是空中楼阁。系统对用户的每一次反馈、每一个行为的学习，最终沉淀为一个对这个人的理解模型。反过来，用户看到系统对自己的描述，会觉得"它确实了解我"，从而对系统给出的规划更有信任感。

功能描述：

系统在用户使用过程中逐步构建多维度画像，涵盖但不限于：

| 画像维度 | 数据来源 | 示例标签 |
|---------|---------|---------|
| 学习风格 | 用户反馈趋势 + 资源偏好记录 | 理解偏慢但记忆牢固 / 快速吸收但容易遗忘 / 边练边学型 |
| 最佳学习时段 | 打卡时间分布 | 晨型学习者 / 夜猫子型 / 碎片化学习者 |
| 学习节奏偏好 | 任务完成速度 vs 预估时间 | 稳健型(扎实为主) / 冲刺型(喜欢快速推进) |
| 反馈校准基线 | 用户说"太难"时对应的实际掌握度 | 标准严格型 / 标准宽松型 |
| 持续力 | 中断历史记录 | 稳定型 / 间歇型(需要外部督促) |
| 知识保留特征 | 复习正确率趋势 | 短期记忆强 / 长期记忆需要多轮巩固 |

用户可见的画像页面：

系统提供一个专属页面，让用户能看到系统对自己的认知：

你的学习画像 — 已通过24次反馈更新

学习风格：理解偏慢但记忆牢固型
  你对新概念的第一遍理解通常需要多一些时间，但一旦掌握之后记忆非常持久。
  建议：新知识安排充裕时间，复习可以拉长间隔。

最佳学习时段：晚上20:00-22:00
  你过去两周80%的学习活动发生在这个时段。
  建议：把最重要的学习任务安排在这个时段。

反馈习惯：标准严格型
  你说"太难了"时，实际正确率通常在60%以上。你对自己的要求比较高。
  系统已据此校准，在你反馈"太难"时会给予更多重视。

持续力：间歇型（平均每10天会有一次2-3天的中断）
  建议：不要设置过于紧凑的计划，留有缓冲空间。

设计要点：
- 画像不是一次性生成的，而是随每次反馈持续进化
- 画像页面本身就是一种干预——用户看到"我原来是这样的学习者"，会更有意识地调整行为
- 画像驱动所有其他P0功能：目标评估的措辞、反馈问题的生成方式、路径调整的策略，都以画像为基础
- 新用户无数据时，系统在首次使用中通过摸底测验+简单偏好询问建立初始画像

### 功能 ③：目标设定与可行性评估

用户需求：我不知道"3个月入门数据分析"这个目标现不现实。

功能描述：
- 用户输入自然语言目标（"想3个月后能自己写爬虫"）
- 系统解析目标，拆解为所需知识点清单
- 系统根据用户的画像（持续力、学习节奏偏好、每天实际可用时间等），给出个性化可行性评估

评估示例（结合画像版）：

"根据你的学习记录，你属于理解偏慢但记忆牢固的类型，且过去一个月平均每天实际学习时间是35min。以这个节奏，完成Python入门预计需要10周，比你预期的3个月还宽松一些。不过你目前的英语计划也在同时运行，建议把Python设为高优先级，英语设为中优先级，避免两边都不够时间。"

设计要点：
- 可行性评估引用用户画像数据，让建议有据可依
- 评估结果用自然语言呈现

---

### 功能 ④：学习路径自动生成

用户需求：目标定了，但每天该学什么？按什么顺序学？

功能描述：
- 系统将目标拆解为里程碑 + 知识节点序列
- 每个知识节点包含：学习主题、预估学习时长、前置依赖
- 路径生成时参考用户画像：
  - 稳健型用户：安排更充裕的时间，每阶段留复习日
  - 冲刺型用户：节奏更紧凑，前置知识点优先排列
  - 间歇型用户：路径中自动插入缓冲日，避免一中断就全盘崩塌

设计要点：
- 路径是可视化+可交互的
- 用户可以直接在路径图上标记"我想先学这个"或"跳过这个"

### 功能 ⑤：每日排期与多计划时间协调

用户需求：我想要一张"今天做什么"的明确清单，而且所有计划的时间不能打架。

功能描述：
- 系统读取用户所有活跃计划的当日待办
- 按优先级 + 用户画像中的最佳学习时段 + 可用总时长，自动生成今日合并日程
- 时间冲突时按优先级自动协调

今日日程示例：

今日学习计划 · 总用时60min · 余量30min

早上7:30-7:50 (通勤)
  英语单词复习（英语计划）

中午12:30-13:00 (午休)
  Python函数练习（Python计划）

晚上20:00-20:40 (你的最佳学习时段)
  Python函数进阶（Python计划）
  今日重点：理解位置参数、默认参数、可变参数的区别
  你可以自己在B站/YouTube搜索"Python函数参数"相关教程

晚上20:40-20:50 (放松)
  摄影构图阅读（摄影计划）

设计要点：
- 允许用户手动拖拽调整当天日程
- 用户调整后系统更新画像偏好
- 如果总预算超出可用时间，系统提示并建议

### 功能 ⑥：智能感受反馈（重构版）

用户需求：学完了，我想告诉系统学得怎么样，但我不想填一堆选项。

核心变革：从"系统给固定选项让用户选"变为"系统根据对用户的了解，智能生成开放式追问"。每一次反馈提问都是独一无二的，体现系统对用户的深度认知。

功能描述：

用户在外部完成学习后，回到系统标记"已完成"。此时系统不展示固定选项，而是根据用户的画像和本次学习内容生成个性化问题。

示例场景一：理解偏慢但记忆牢固型用户，刚学完"函数参数传递"

系统根据画像生成提问：

"你上次学'变量作用域'时提到过'概念能理解，但真正写代码的时候容易混'。这次函数参数有没有类似的感觉？还是说因为有了变量作用域的基础，这次顺畅一些？

你可以这样描述：
- 和之前比，这次理解起来是更容易还是更难？
- 写代码的时候有卡住的地方吗？
- 你觉得需要再练练，还是可以往前走了？"

示例场景二：快速理解但容易遗忘型用户，刚学完"文件读写"

系统根据画像生成提问：

"根据你之前的学习模式，你上手新知识通常很快，但一周后容易模糊。这次文件读写的内容，你感觉自己理解到什么程度？

可以聊聊：
- 文件读写的几种模式（r/w/a）你分清了吗？
- 需不需要近期安排一次快速复习来巩固？"

示例场景三：用户已连续3天反馈偏难

系统感知到模式，调整提问策略：

"这周连续三天你都说内容有点吃力。我查看了一下，这周的知识密度确实比上周高了大约40%。是内容跳跃太大了，还是每天的学习时长不太够？或者说你觉得这个方向的学习方式需要调整？比如换一种方式学习？"

示例场景四：新用户，画像尚未建立

系统坦诚地提问：

"你是第一次反馈，我还不太了解你的学习习惯。今天学完'变量与类型'，你整体的感受如何？你可以随便说说，比如这些内容对你来说是新的还是大部分都知道？理解起来顺畅吗？"

设计要点：
- 每一轮反馈提问都是系统根据画像+当次学习内容实时生成的，不重复
- 提问中附带引导提示("你可以这样描述")，降低用户的表达门槛
- 系统可以追问——如果用户的回答比较简短，系统可以问"能再多说一点吗？"
- 用户的回答除了更新学情，还会被用于进一步丰富用户画像
- 一次反馈交互可以像一次简短的对话，而不是填表

反馈后的交互：

用户提交感受后，系统立即回应，让用户看到"它听了，它动了"：

"明白了。函数参数这块你觉得需要再巩固，我把明天的计划从'函数进阶'改为'函数练习题+复习'，等练熟了再往后走。"

"看来变量作用域对你来说偏简单了。我把这部分压缩到1天，后面数组提前开始。明天起节奏会快一些，如果觉得跟不上了随时告诉我。"

### 功能 ⑦：反馈驱动的即时重规划

用户需求：我反馈完了，然后呢？系统不能光记录不行动。

功能描述：每次用户提交反馈后，监督反馈Agent立即基于画像和反馈内容进行评估，触发相应动作。

响应对照表（以画像校准后的尺度为准）：

| 用户表达的核心信号 | 系统动作 | 调整策略 |
|-----------------|---------|---------|
| 内容偏简单，推进顺利 | 标记掌握度提升，压缩后续 | 前置后续内容；当天剩余时间问是否加学其他计划 |
| 难度适中，正常通过 | 正常推进 | 保持节奏 |
| 理解了但需要巩固 | 安排近期复习 | 2-3天后插入复习任务 |
| 没搞懂，需要调整 | 标记薄弱，诊断原因 | 拆细重排，延长时长，调整资源类型建议 |
| 没学完，时间不够 | 评估是内容太多还是安排不合理 | 压缩单次任务量，增加频次 |
| 连续反馈吃力 | 主动降强度建议 | 弹出建议降低每日总预算 |

交互要点：
- 重规划后，系统以自然语言告知用户调整了哪里，而不是静默更新
- 调整的理由引用画像数据，让用户觉得"有道理"

"收到你的反馈。考虑到你属于理解偏慢但记忆牢固的类型，数组这部分我不赶进度，拆成3天慢慢学。同时换成了侧重练习的方式——多写代码比多看视频对你更有效。"

"你这周连续反馈吃力，看了一下每日预算还在60min，但过去一周实际学习时长平均只有35min。可能不是内容难，是每天安排的量偏多了。我把预算调到45min试试？"

## 3.3 第二层：增强体验（P1，应该实现）

### 功能 ⑧：遗忘干预

产品洞察：自学最大的浪费是"学了就忘"。大多数自学者不会主动安排复习。

功能描述：
- 系统对每个已标记"已掌握"的知识点，根据用户画像中的知识保留特征，个性化安排复习节点
- 记忆保留强的用户：拉长复习间隔；容易遗忘的用户：加密复习频率
- 复习以轻量形式插入计划，复习结果纳入学情更新

---

### 功能 ⑨：学习重点指引

用户需求：系统让我"学函数参数传递"，但我去了B站搜什么？从哪开始？

功能描述：
- 系统不提供具体资源链接，而是提供学习方向性指引
- 每个学习任务附带：学习主题 + 重点关注什么 + 建议练习方向
- 用户拿着这个指引去自己找资源

示例：

Python函数基础 · 今日任务

学习主题：函数参数传递
重点理解：
- 位置参数和关键字参数的区别
- 默认参数的使用场景
- *args和**kwargs有什么用

建议练习：
写一个小程序，分别用三种参数传递方式实现同一个加法函数
尝试用*args实现一个不限定参数个数的求和函数

搜索关键词参考：Python函数参数、args kwargs

设计要点：
- 提供搜索关键词参考，降低用户的搜索成本
- 建议练习比单纯"学习"更有价值
- 用户如果反馈"这个方向不对"，系统记录并调整

---

### 功能 ⑩：学习日记

产品洞察：学习中灵光一现的感悟、绕了很久才懂的点，如果不记下来，下次遇到又要重新绕一次。

功能描述：
- 完成每个学习活动时，可选择性写一句话笔记
- 系统根据画像给出不同的引导提示：
  - 容易遗忘型用户：记录一下今天最难理解的点，方便以后复习时重点关注
  - 理解偏慢型用户：把你的理解用自己的话写下来，写出来才算真的懂了
- 在后续复习时推送历史笔记
- 笔记按知识点分类归档

### 功能 ⑪：中断恢复模式

产品洞察：自学中断是常态，不是意外。但大多数规划工具假设用户会每天使用。

功能描述：
- 检测到用户连续3天未登录，记录中断开始
- 用户回来后，根据画像中的持续力数据，个性化生成恢复方案
- 持续力强的用户：可直接从断点继续
- 间歇型用户：低强度恢复周，避免又一次放弃
- 中断超过7天时，安排快速摸底测验，根据当前真实水平重新规划

交互要点：语气温和，不指责

"你已经有6天没学习了，没关系。根据你的学习记录，之前中断后恢复时如果安排得太满反而容易再次中断。这次我们慢慢来，先每天20分钟，找回状态再说。"

### 功能 ⑫：每周学习简报

用户需求：学了一周，我到底进步了多少？

功能描述：
- 每周一自动生成上周的学习简报
- 内容结合画像数据，比单纯进度数据更有深度

示例：

第3周学习简报

本周投入5.5小时，比上周多了1小时

Python函数：掌握度40% -> 75%
Python文件：掌握度0% -> 35%
英语词汇：掌握度60% -> 65%

你的学习画像本周更新：
确认你属于"理解偏慢但记忆牢固"类型
函数部分花了比预期多2天，但一旦掌握后测试正确率达到90%
这个节奏适合你，不用着急赶进度

薄弱提醒：文件读写（35%）已连续3天反馈偏难
建议：下周安排2天集中突破

### 功能 ⑬：学习画像展示与进化

用户需求：系统到底怎么看我？我觉得它准不准？

功能描述：
- 提供一个专属的"我的画像"页面
- 画像随每次反馈持续更新，用户可以看到自己画像的变化历史
- 用户可以对画像标签进行反馈："我觉得这个判断不准"——系统据此调整

# 第四部分：用户完整旅程

## 4.1 新用户首日流程

第1步：注册 -> 进入欢迎页
  "欢迎来到学伴。你目前想学什么？"

第2步：创建第一个计划
  "我想3个月入门Python，能写小项目"
  -> 系统解析目标，显示可完成性评估
  -> 用户确认 -> 路径生成

第3步：简单初始画像建立
  系统通过几个简单问题建立初始画像：
  "你过去学过编程吗？"
  "你平时是喜欢一口气学完，还是慢慢来、扎实一些？"
  "你觉得自己学新东西快吗？"
  -> 系统生成初始画像标签（待后续数据修正）

第4步：查看今日计划
  系统自动生成第1天的任务
  -> 用户看到"今天学什么" + 学习重点指引
  -> 系统说："今天学变量和类型，重点关注变量命名规则和常见数据类型区别。你可以去B站搜'Python变量类型'相关教程。"

第5步：去外部学习
  用户带着系统给的重点方向去B站/书籍/课程学习

第6步：回来反馈
  用户标记完成，系统根据初始画像生成第一个反馈问题：
  "第一次反馈，我对你还不了解。今天学完变量和类型感觉怎么样？之前有基础吗？还是完全新的？"

第7步：看到系统响应
  "收到！你说大部分都知道，那我明天直接跳过变量这部分的练习，从控制流开始。不过你提到f-string是第一次见，明天的计划里我加了个小练习。"

## 4.2 日常使用的一天

08:00  收到推送：今日计划已生成
       打开扫一眼：今天3件事，总用时55min

12:30  午休时间，完成英语单词复习
       回系统标记完成，系统问：
       "今天复习的是第3单元词汇，之前你说这单元生词偏多，现在感觉怎么样？"
       用户回答："大部分记住了，还有十来个容易混"
       系统回复："收到，明天安排那十来个重点词单独过一遍。"

20:00  晚上整块时间，学Python函数
       学完后反馈，系统说：
       "上次你学了基础语法，这次是函数入门。你属于理解偏慢但记得牢的类型，函数这块你觉得呢？和之前变量那部分比难度如何？"
       用户："比变量难一些，但看了一遍视频大概懂了"
       系统回复："懂了但还需要沉淀，后天安排一次函数练习巩固。"

睡前  扫一眼明天的计划，看到函数练习已安排好

## 4.3 中断后恢复

用户因出差5天没登录

归来后第1次打开系统：

  系统基于画像个性化提示：
  "你已经有5天没学习了，没关系。
   根据你的记录，之前中断后恢复时如果安排太满反而容易再次中断。
   这周我安排轻量版，每天只做20分钟，找回状态再说。"

  用户完成第1天任务
  -> 系统检测到回归，第2天逐步加量
  -> 用户连续3天都完成恢复计划，系统说：
     "状态回来了，下周恢复到正常节奏，可以吗？"

新建"英语口语"计划 (二星20min/天)

系统结合用户画像评估：
  "根据你的学习记录，你晚上8-10点效率最高。我会把Python安排在这个时段，英语放在早上通勤时间。两个计划共需50min/天，绰绰有余。"

| 不做 | 理由 |
|------|------|

# 第八部分：产品原则

1. 用户只做两件事：学，以及描述感受。其余系统做。
2. 每一次反馈都是一次对话，不是填表。系统根据对用户的了解主动提问，而不是给出固定选项让用户选。
3. 每一次反馈都要被看见。系统不能沉默地更新，要说"我收到了，我理解你是这个意思，我改了什么、为什么这么改"。
4. 画像是一切智能的基础。没有用户画像，路径生成和反馈分析都是盲人摸象。
5. 系统不教、不给资源、不判对错。它只负责安排、提醒、记录、建议。学习本身发生在系统之外。
6. 用户中断是常态，不是错误。系统不指责、不惩罚，提供低门槛的回归路径。
7. 比完美更重要的是被使用。宁可功能少而精，不可功能多而繁。
