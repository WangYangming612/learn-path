**Step 5 核心代码结构示意：**

```python
# orchestrator.py (简化示意)
intent_graph = StateGraph(AgentState)

# 意图识别节点 -> 用 LLM 将用户输入分类
intent_graph.add_node("intent_classifier", call_llm_to_classify_intent)

# 条件边 -> 根据意图路由到不同子图
intent_graph.add_conditional_edges(
    "intent_classifier",
    router_map={
        "create_plan": "plan_agent",
        "submit_feedback": "feedback_agent",
        "view_profile": "profile_agent",
        "other": "fallback_handler",
    },
)
```

| LLM API 不可用/限流 | 中 | 高（所有 Agent 依赖 LLM） | 本地部署 Ollama 作为 fallback，每个 Agent 调用加 retry+timeout |

| Agent 间数据契约频繁变更 | 中 | 中 | 先定接口再实现，contracts 文档实时更新，变更时群内通知 |
| 前端等待后端 API 阻塞 | 高 | 中 | C 先用 mock 数据开发，Step 6/7/9 API 稳定后再替换真实接口 |
| ChromaDB + SQLite 事务不一致 | 低 | 高 | 画像数据以 PostgreSQL/SQLite 为准，ChromaDB 仅做向量检索辅助 |
| 格项目周期紧张 | 中 | 中 | P2 功能全部砍掉只做 P0+P1；P1 功能如果时间不够就只做 H(遗忘干预) |
