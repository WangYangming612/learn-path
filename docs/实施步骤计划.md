# 个性化学习路径动态生成系统 — 实施步骤计划

> **版本**：v1.0
> **日期**：2026-07-23
> **核心原则**：每步产出可运行、可验证的最小可用产品（MVP），遵循企业级多智能体系统开发流程
> **Git 策略**：每步完成后 commit + tag，保证可随时回退到任意步骤
> **教学框架**：每步遵循 3W1H（What/Why/Which/How）讲解，代码含中文注释

## 一、项目架构全景图

```
                     +--------------------------------------+
                     |        前端层 (React + Vite)          |
                     |  Dashboard / Plans / DailyView       |
                     |  Feedback / Profile                  |
                     +------------------+-------------------+
                                        | HTTP / SSE / WebSocket
                     +------------------v-------------------+
                     |      API 网关层 (FastAPI)             |
                     |  JWT 鉴权 / 路由分发 / SSE 推送       |
                     +------------------+-------------------+
                                        |
                     +------------------v-------------------+
                     |      多智能体编排层 (LangGraph)        |
                     |                                      |
                     |   +-------- Orchestrator Agent -----+ |
                     |   | 意图识别/子图路由/结果聚合       | |
                     |   +-+------+------+------+------+--+ |
                     |     |      |      |      |      |    |
                     |  +--v-+ +-v---+ +-v--+ +-v--+ +-v-+ |
                     |  |Prof | |Plan | |Sched| |Feed| |Int | |
                     |  |Agent| |Agent| |Agent| |Agent| |Agt| |

                                        |
                     +------------------v-------------------+
                     |      存储层                           |
                     |  PostgreSQL/SQLite / ChromaDB / Redis |
                     +--------------------------------------+
```

### 智能体职责矩阵

| 智能体 | 核心职责 | 关键数据依赖 |
|--------|---------|-------------|
| **Orchestrator** | 意图分类 + 子图路由 + 会话记忆管理 + 结果聚合 | 用户输入、会话上下文 |
| **Profile Agent** | 多维度画像推算 + 标签演化 + 画像漂移检测 | 反馈历史、打卡时间、任务完成率 |
| **Plan Agent** | 目标结构化解析 + 知识图谱生成 + 基于画像的路径调优 | 学习目标、画像数据 |
| **Schedule Agent** | 多计划优先级排序 + 时间段优化 + 冲突消解 | 活跃计划、画像时段偏好、时间预算 |
| **Feedback Agent** | 画像感知追问生成 + 反馈信号语义解析 + 掌握度推断 | 画像数据、当前学习内容、反馈历史 |
| **Intervention Agent** | 中断检测 + 恢复方案生成 + 遗忘曲线排期 | 画像持续力数据、中断记录 |

### 3. 3W1H 讲解方式

| 问题 | 英文 | 讲解内容 |
|------|------|----------|
| What（是什么） | What | 这个技术/设计是什么？它的定义和核心概念 |

### Step 3：用户认证系统 + JWT + FastAPI 路由

| 项目 | 内容 |
|------|------|
| **目标** | 实现注册/登录/JWT 鉴权完整链路 |

| **MVP 效果** | `POST /api/v1/auth/register` 创建用户；`POST /api/v1/auth/login` 返回 JWT；受保护路由携带 Token 可访问 |
| **Git** | commit + tag `step-3-auth` |

#### 本步涉及的技术与设计

| 技术/设计 | What | Why | Which | How |
|-----------|------|-----|-------|-----|
| **JWT (JSON Web Token)** | 无状态认证令牌，签名防篡改 | RESTful API 的标准认证方案，无需服务端 Session | Session-Cookie（有状态，不适合前后端分离） vs JWT（无状态，自包含），选 JWT | `python-jose` 生成和验证，`access_token` 有效期 7 天 |
| **密码哈希 (bcrypt)** | 密码单向哈希加盐存储 | 用户密码不应明文存储 | md5/sha256（可暴力破解） vs bcrypt（慢哈希+自动加盐），选 bcrypt | `passlib.hash.bcrypt`，`hash()` 和 `verify()` |
| **FastAPI 依赖注入** | FastAPI 的 `Depends()` 机制 | 将鉴权逻辑声明为依赖，路由函数只需声明依赖即可 | 中间件（全局拦截不够灵活） vs 依赖注入（路由级控制），选依赖注入 | `async def get_current_user(token = Depends(oauth2_scheme))` |

### Step 5：LLM 客户端 + Agent 状态定义 + Orchestrator 骨架

| 项目 | 内容 |
|------|------|
| **目标** | 实现 LLM 统一客户端，定义 LangGraph Agent 状态基类，搭建 Orchestrator Agent 骨架（意图分类 + 子图路由） |

#### 本步涉及的技术与设计

| 技术/设计 | What | Why | Which | How |
|-----------|------|-----|-------|-----|
| **LangGraph StateGraph** | LangChain 的子图编排框架，用有向图定义 Agent 状态流转 | 原生支持子图嵌套、状态共享、条件边和循环边 | CrewAI（无子图嵌套） vs AutoGen（配置复杂） vs LangGraph（同生态、子图原生），选 LangGraph | `StateGraph(AgentState)` + `.add_node()` + `.add_edge()` + `.add_conditional_edges()` |
| **Orchestrator 模式** | 一个网关 Agent 统一接收请求，根据意图分发到子 Agent | 单一入口、统一状态管理、职责分离、可扩展 | 点对点 Agent 通信（复杂耦合） vs Orchestrator（中心化编排），选 Orchestrator | Orchestrator 维护 `intent -> subgraph` 路由表 |
| **AgentState TypedDict** | 通用智能体状态基类，用 TypedDict 定义 | 类型安全、结构清晰、子 Agent 可扩展 | Pydantic BaseModel（重） vs TypedDict（轻量+类型提示），选 TypedDict | 定义 `messages`、`user_id`、`plan_id`、`session_id`、`agent_type`、`tools`、`next` |
| **ChatOpenAI 统一客户端** | 封装 LangChain 的 ChatOpenAI，统一 API | 隔离 LLM 调用细节，方便切换 provider | 每个 Agent 直接实例化 ChatOpenAI（重复配置） vs 统一客户端（单例），选统一客户端 | `LLMClient(config)` 封装 `ChatOpenAI(base_url=..., model=...)` |


### Step 6：Profile Agent -- 画像构建与维护

| 项目 | 内容 |
|------|------|
| **目标** | 实现 Profile Agent 子图：摸底问答生成初始画像、画像维度更新、画像持久化到 PostgreSQL + ChromaDB |
| **涉及文件** | `backend/app/agents/profile_agent.py`、`backend/app/llm/prompts/profile.py`、`backend/app/schemas/profile.py`、`backend/app/api/v1/profile.py`、`backend/app/core/profile_service.py` |
| **MVP 效果** | 新用户首次访问 `/api/v1/profile` 触发摸底问答流程，回答 3-5 个问题后生成初始画像并存储 |
| **Git** | commit + tag `step-6-profile-agent` |

#### 本步涉及的技术与设计

| 技术/设计 | What | Why | Which | How |
|-----------|------|-----|-------|-----|
| **画像维度建模** | 用户画像由 6 个固定维度构成：学习风格、最佳时段、学习节奏、反馈基线、持续力、知识保留 | 维度固定便于标准化存储和对比；每个维度附带置信度分数 | 自由标签体系（难以标准化） vs 固定维度+动态标签（兼顾），选后者 | Pydantic dataclass 定义，每个字段为 `{label, confidence}` |
| **多轮摸底问答** | Profile Agent 通过 3-5 个自然语言问题摸底，逐步填充画像 | 新用户无数据时快速建立初始画像 | 无画像冷启动（盲目推荐） vs 填选项（生硬） vs AI生成式问答（自然），选AI生成式问答 | Profile Agent 生成追问，用户回答后 LLM 提取特征，更新置信度 |
| **ChromaDB 向量存储** | 画像维度向量化，支持语义检索和画像漂移检测 | 画像更新时可语义检索历史反馈 | PostgreSQL JSON（无向量索引） vs ChromaDB（向量索引原生），选 ChromaDB | `collection.upsert(ids, embeddings, metadatas)` |
| **策略模式** | 每个画像维度的更新算法独立封装 | 新增维度不需要修改 Profile Agent 主体逻辑 | if-else（硬编码） vs 策略模式（开闭原则），选策略模式 | 每个维度实现 `ProfileDimensionStrategy` 接口 |

| **MVP 效果** | 用户输入"我想 3 个月入门 Python"，Plan Agent 返回结构化知识节点列表（含依赖关系、预估学时），路径时间按画像系数调整 |
| **Git** | commit + tag `step-7-plan-agent` |

#### 本步涉及的技术与设计

| 技术/设计 | What | Why | Which | How |
|-----------|------|-----|-------|-----|
| **LLM 结构化抽取** | 用 LLM 从自然语言中抽取目标领域、预期时间、当前基础、期望深度 | 用户输入自由文本，系统需要结构化存储和计算 | 正则/关键词（脆弱） vs LLM 抽取（语义理解），选 LLM 抽取 | `with_structured_output()` 或 function calling |
| **知识图谱 DAG 生成** | 将学习目标拆解为有向无环图（DAG），每个节点是一个 atomic learning unit | 学习路径本质是前置依赖拓扑结构 | 线性列表（无法表达依赖） vs DAG（可拓扑排序、可视化），选 DAG | LLM 输出节点列表 + `prerequisite_ids`，服务层拓扑排序 |
| **画像自适应系数** | 路径时间乘以画像系数：稳健型 1.3x，冲刺型 0.8x，间歇型插入 20% 缓冲日 | 让路径适配用户的节奏偏好 | 统一估算（不准确） vs 画像系数调整（个性化），选后者 | Plan Agent 读取 Profile Agent 画像，乘积调整 `estimated_minutes` |
| **用户干预拓扑重算** | 用户标记"跳过/优先"后，Plan Agent 重新拓扑排序 | 系统应尊重用户判断 | 忽略（专断） vs 重拓扑排序（灵活适配），选后者 | 修改 `prerequisite_ids` 和 `order_index`，重新拓扑排序 |

#### 本步涉及的技术与设计

| 技术/设计 | What | Why | Which | How |
|-----------|------|-----|-------|-----|
| **优先级-时段分配算法** | 按计划优先级 + 画像时段偏好 + 可用时长，生成最优时间段分配 | 多计划冲突时需明确协调策略 | 简单轮询（无优先级） vs 优先级加权分配（符合用户意图），选后者 | 高优先级优先占据画像最佳时段；低优先级填剩余时段 |

| **手动拖拽反馈** | 用户调整后 Schedule Agent 更新画像时段偏好权重 | 拖拽行为是隐式数据反映真实偏好 | 忽略（丢失信息） vs 更新画像（持续学习），选后者 | 分析变化方向，调整 `time_preference` 权重 |
| **学习重点指引生成** | 排期时为每个任务生成"重点理解+建议练习" | 用户需要知道学什么、重点是什么 | 仅标题（笼统） vs 生成指引（可操作），选后者 | LLM 极简 prompt 生成指引，存入 `DailyTask.guide_content` |
